# PhishShield Mathematical Architecture

This document thoroughly details the end-to-end mathematical foundation, algorithms, formulas, and probability scaling mechanisms utilized across the three core PhishShield ML engines (URL, SMS, and Email).

---

## 1. URL Engine (LightGBM Multiclass Model)

### Algorithm Overview
The URL Engine leverages **LightGBM (Light Gradient Boosting Machine)**, utilizing a highly efficient Leaf-wise Gradient Boosting Tree mechanism. For our 4-class classification problem (`benign`, `defacement`, `malware`, `phishing`), LightGBM builds an ensemble of $T$ sequential decision trees. Instead of growing trees level-by-level, it splits the leaf with the maximum loss reduction, prioritizing accuracy. 

### Raw Margin Scores (Logits)
Each class $k$ (where $k \in \{0, 1, 2, 3\}$) receives an independent score aggregated across all trees. The raw logit score for class $k$ is calculated by summing the decision values $f_{t, k}$ from each tree $t$ for a given input feature vector $\vec{x}$:

$$z_k = \sum_{t=1}^{T} f_{t, k}(\vec{x})$$

### Probability Scaling (Softmax Function)
Because raw logits ($z_k$) can span from negative to positive infinity, they must be converted into normalized confidence percentages. We use the **Softmax Function** to scale these multi-class raw scores into a probability distribution summing to 1.

$$P(Y = k \mid \vec{x}) = \frac{e^{z_k}}{\sum_{j=0}^{3} e^{z_j}}$$

### Numerical Walkthrough
Consider a scenario where the LightGBM ensemble produces the following raw logits for a suspicious URL:
* `benign` ($z_0$): -4.013
* `defacement` ($z_1$): -8.032
* `malware` ($z_2$): -2.888
* `phishing` ($z_3$): 1.337

**Step 1: Exponentiation ($e^{z_k}$)**
* $e^{-4.013} \approx 0.018$
* $e^{-8.032} \approx 0.0003 \approx 0.0$
* $e^{-2.888} \approx 0.056$
* $e^{1.337} \approx 3.808$

**Step 2: Denominator Summation**
$\sum e^{z_j} = 0.018 + 0.0 + 0.056 + 3.808 = 3.882$

**Step 3: Percentage Output**
* `benign`: $0.018 / 3.882 = 0.46\%$
* `defacement`: $0.0 / 3.882 = 0.01\%$
* `malware`: $0.056 / 3.882 = 1.44\%$
* `phishing`: $3.808 / 3.882 = 98.09\%$

Final prediction: **Phishing** with $98.09\%$ confidence.

## 2. SMS Engine (Calibrated LinearSVC Model)

### Algorithm Overview
The SMS Engine uses **Support Vector Classification (LinearSVC)**. It operates effectively on high-dimensional, sparse matrices generated by merging TF-IDF vectorization with tabular mobile metadata (e.g., phone number counts, URL presence, shouting ratios). LinearSVC seeks the optimal linear hyperplane that maximizes the margin separating safe (`ham`) texts from malicious (`spam`, `smishing`) texts.

### Decision Function (Hyperplane Margin)
The prediction relies on the geometric distance of the input vector $\vec{x}$ from the learned decision boundary. This margin score $f(\vec{x})$ is defined by the weight vector $\mathbf{w}$ and the bias term $b$:

$$f(\vec{x}) = \mathbf{w}^T \vec{x} + b$$

### Probability Calibration (Platt Sigmoid Scaling)
LinearSVC natively outputs unbounded distance margins, not probabilities. To support confidence scoring, we wrap the model in `CalibratedClassifierCV`, which applies **Platt Scaling**. Platt Scaling learns a logistic regression model over the raw SVM margin scores.

$$P(Y = k \mid \vec{x}) = \frac{1}{1 + e^{A \cdot f(\vec{x}) + B}}$$
*(Where $A$ and $B$ are parameters learned via cross-validation during training).*

### Normalization Step
For multiclass scaling (e.g., `ham`, `spam`, `smishing`), Platt scaling computes independent one-vs-rest binary probabilities. These raw, independent probabilities do not inherently sum to 100%. Therefore, an explicit L1 normalization is applied where each class probability is divided by the sum of all class probabilities.

### Numerical Walkthrough
Assuming a binary scenario (simplified for clarity) for an SMS message:
* Margin distance computed by LinearSVC: $f(\vec{x}) = 1.45$
* Learned Platt parameters: $A = -1.2, B = 0.3$

**Calculation:**
* $Exponent = (-1.2 \cdot 1.45) + 0.3 = -1.74 + 0.3 = -1.44$
* $e^{-1.44} \approx 0.2369$
* $P(Y=1) = \frac{1}{1 + 0.2369} = \frac{1}{1.2369} \approx 0.808$

The message has an $80.8\%$ probability of being malicious.

## 3. Email Engine (Calibrated LinearSVC + 3-Layer Stacked Logic)

### Algorithm & Pipeline Overview
The Email Engine employs a **LinearSVC combined with CalibratedClassifierCV**. It processes a massive feature space constructed from a 5,000-dimensional TF-IDF array and 30 dense structural metadata features (e.g., uppercase ratios, urgency keyword counts). 

### Platt Sigmoid Math
Because the email dataset is configured for binary classification (`ham` vs. `phishing`), the Platt calibration yields a direct probability map via the standard Sigmoid function over the SVM margin, requiring no complex multi-class normalization:

$$P(\text{Phishing} \mid \vec{x}) = \frac{1}{1 + e^{A \cdot f(\vec{x}) + B}}$$
$$P(\text{Ham} \mid \vec{x}) = 1 - P(\text{Phishing} \mid \vec{x})$$

### Stacked Security Override Logic (Mathematical & Boolean Rules)
Regardless of the NLP model's baseline calculation, the Email Engine employs deterministic, rule-based overrides acting as a final safeguard layer.

**Layer 1 (Cross-Model URL Override):**
If the email contains embedded URLs, those URLs are extracted and passed to the *URL Engine*. If the URL Engine detects malicious intent above a strict threshold, the Email Engine's baseline prediction is completely overridden.
$$ \text{IF } \left( P_{\text{url-engine}}(\text{malicious}) \ge 0.35 \right) \rightarrow \text{Override output to Phishing} $$

**Layer 2 (Short-Text Urgency Safeguard):**
Short, direct social engineering templates often lack sufficient statistical variance for NLP detection. A boolean constraint targets these.
$$ \text{IF } (\text{len}(\vec{x}) < 500) \land \left( \sum \text{PhishSignals}(\vec{x}) \ge 2 \right) \rightarrow \text{Override output to Phishing} $$

### Numerical Walkthrough (Standard vs. Override)

**Scenario A: Standard Probability Calculation**
1. **Raw SVM Margin:** $f(\vec{x}) = 0.565$
2. **Platt Scaling Output:** $P(\text{Phishing}) = 0.8214 \ (82.14\%)$
3. **Layer 1 Check:** No URLs found $\rightarrow$ Pass.
4. **Layer 2 Check:** Length is 1200 $\rightarrow$ Pass.
5. **Final Output:** Phishing ($82.14\%$) based on standard mathematical probability.

**Scenario B: Stacked Security Override**
1. **Raw SVM Margin:** $f(\vec{x}) = -0.75$ (Model leans towards `ham`).
2. **Platt Scaling Output:** $P(\text{Phishing}) = 0.12 \ (12\%)$
3. **Layer 1 Check:** A URL in the email is scanned. The URL model returns $P(\text{phishing}) = 0.98 \ (98\%)$.
4. **Override Triggered:** Since $0.98 \ge 0.35$, the ML probability mapping is discarded.
5. **Final Output:** Hard override to `phishing` ($100\%$) citing the detected malicious link as the definitive vector.
